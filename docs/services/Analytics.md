# Analytics

`AnalyticsService` — аналитика и метрики.

## Методы

### Кастомные события
- `SendEventAsync(metricId)` — отправить событие без параметров (`metricId` — id события из консоли)
- `SendEventAsync(metricId, parameters)` — с параметрами (`Dictionary<string, string>`)
- `EnqueueEvent(eventKey, parameters, tags)` — добавить в очередь для batch-отправки (буфер работает, только пока идёт трекинг; до входа событие отбрасывается). `eventKey` — **ключ** события из консоли: он не меняется при переименовании события, в отличие от названия.

### Batch
- `SendBatchAsync(events)` — отправка пакета событий (`List<BatchEventItemDto>`). Событие задаётся ключом в `EventKey`; `EventName` — то же значение для серверов без ключей событий (новый сервер читает `EventKey`, а если его нет — `EventName`). Сервер отвечает 200 `{ published, errors }` даже если отклонил все события; SDK пишет warning с числом отклонённых и `index`/`code`/`error` первых трёх.
- Неуспешный запрос аналитики SDK логирует с кодом облачной ошибки (`CloudErrorCodes`), а не только с HTTP-статусом.

### Системные метрики
- `SendSessionStartedAsync()` — начало сессии (SDK шлёт его сам, ровно один раз на игровую сессию; ручной вызов засчитает текущую сессию повторно)
- `SendPlaytimeAsync(playTimeInMinutes)` — время игры

## Кто записан в событии

Каждая запись в аналитике несёт и аккаунт, и профиль: сервер берёт их из токена (`PlayerId` — аккаунт, `SelectedProfileId` — выбранный профиль). В консоли игроков можно считать по профилям или по аккаунтам — переключение профиля даёт нового игрока по профилям, но того же — по аккаунтам.

- Токен без выбранного профиля сервер отклоняет с `game_analytics.profile_id_header_required` (`CloudErrorCodes.GameAnalyticsProfileIdHeaderRequired`); без аккаунта — `game_analytics.player_id_header_required`.
- Смена профиля (`PlayerAccount.SelectProfileAsync`, `CreateProfileAsync(dto, autoSelect: true)`): до переключения SDK отправляет буфер событий и неотчитанный playtime (если набралось хотя бы полминуты) — ещё от старого профиля; после refresh токена начинается новая игровая сессия (новый `SessionId` и один `SessionsStarted`) — уже от нового.

## Игровая сессия

- `SessionId` — текущая **игровая** сессия (Guid). Уходит заголовком `AnalyticsSessionId` в каждом запросе аналитики; `null`, пока аналитика не запущена, и после выхода.
- Это не `Authentication.SessionId`: auth-сессия живёт, пока жив refresh token, и при восстановлении входа одна на много запусков.
- Игровая сессия = один вход в игру. Новая (и ровно один `SessionsStarted`): запуск с входом или восстановлением сохранённой сессии (`InitializeAsync`); вход после выхода; вход другим аккаунтом; переключение на другой профиль аккаунта.
- Не меняют сессию: возврат из фона (сколько бы он ни длился), привязка провайдера (`OnLogin` того же аккаунта), refresh токена после 401. Следующий запуск приложения — уже новая сессия.
- Время в фоне не считается playtime. Фон — пауза приложения, а на WebGL/десктопе (там при уходе паузы нет) ещё и потеря фокуса. На мобильных фокус не учитывается: его забирают экранная клавиатура, шторка уведомлений, системные диалоги, пока игрок в игре.
- Выход, `ClearLocalSession`, unlink и истечение сессии останавливают трекинг; неотправленные события из буфера отбрасываются (warning в логе).
